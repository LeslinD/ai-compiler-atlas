From Resource Flow to Executable Tests

Tile Fuzz并发 Rust 测试语义模型与可执行测试原型

中文理解：先用资源流和并发关系确定测试场景，再让大模型完成 Rust 代码实现
论文版本：arXiv:2607.21530v1，2026 年 7 月 23 日
来源：arXiv 论文页

先给结论

输入是并发有状态 Rust API 的资源、生命周期和允许的操作；系统先用 Petri 网构造合法、接近非法和高冲突的并发场景，再约束大模型把场景写成可执行测试；输出是保留原场景意图的 Rust 测试和分层判定结果。

读懂它需要的最少背景

并发有状态 API 的行为会随着资源状态不断变化。例如一个有界通道可能处于可发送、已满、已关闭或等待接收等状态。测试还要考虑多个线程的操作顺序。只给大模型一个函数签名，它很容易生成违反前置条件的调用，也可能把并发代码写成实际串行执行。

Petri 网（Petri Net）是一种表示资源状态和事件关系的模型。圆点或位置表示状态，变迁表示可以发生的操作，令牌表示当前有哪些资源。它适合描述“发送后通道变满”“接收后容量释放”这类状态变化。

3 分钟理解

总览。这篇论文把测试生成拆成两项工作。语义模型决定测试要经历哪些状态、哪些操作能够并发、哪些顺序必须保持；大模型只负责把这个已经确定的场景写成 Rust 代码。这样，测试的深度和并发性由模型控制，代码实现的低成本由大模型提供。

旧方法。纯大模型生成通常从 API 文档和函数签名直接写测试。以容量为 1 的异步通道为例，模型可能连续执行两次发送，却没有安排接收者释放容量；也可能先等待接收再创建发送任务，导致测试阻塞。另一类模型驱动测试可以精确枚举状态，但研究者往往要手工编写大量适配代码，才能把抽象路径变成 Tokio 或 Loom 可以运行的测试。

问题位置。真正缺失的部分位于抽象场景和可执行代码之间。抽象模型知道测试想表达什么，大模型知道 Rust 代码怎样写，但两者没有稳定接口。只在生成后检查编译和结果，无法保证代码仍然保持原来的并发关系。

新方法的总思路。作者把 Petri 网产生的场景变成受约束的中间表示。中间表示规定资源状态、事件、因果关系和允许交换顺序的操作。大模型可以选择具体变量、任务和 API 写法，但不能改变这些核心关系。

建立资源模型。把通道、锁、句柄或连接的生命周期编码为带颜色令牌。颜色用于区分不同资源实例和状态。
生成场景。从模型中导出合法深状态场景、只差一个条件就非法的边界场景，以及包含可交换事件的部分序并发场景。
约束代码生成。把场景交给大模型，并用局部忠实性合同规定每个关键事件必须出现，事件间的因果关系不能被改写。
结构修复和调度塑形。若代码丢失任务、屏障或事件，系统只修复结构。随后优先探索冲突较强的合法调度，而不是随机运行一次。
分层判定。分别判断代码是否成功生成、是否保持场景结构、结果和不变量是否正确，以及是否出现死锁或活锁。

完整例子。设有一个容量为 1 的 Tokio MPSC 通道。场景要求生产者发送消息 A，消费者接收 A，另一个生产者发送 B，最后关闭通道。A 的发送必须先于 A 的接收，B 的发送要等容量释放，但关闭与部分读取操作可能存在两种合法顺序。Petri 网先给出这两种线性化。大模型再生成两个异步任务和必要的同步点。若模型把两次发送写在同一任务里并等待完成，结构检查会发现并发关系被压扁；若模型遗漏关闭操作，也会在场景忠实性检查中被拒绝。

回扣。方法有效的原因是，它把“测试语义”从代码生成者手里拿出来，变成独立可检查的约束。它依赖较准确的 API 状态模型，也需要测试框架能够控制并观察调度。模型不完整时，生成的测试仍可能遗漏真实行为。

关键机制再拆一层

关键机制是部分序场景。测试不必提前固定所有线程的全局顺序，只固定真正的因果关系。这样既避免生成非法调用，又保留并发调度的变化空间。

另一个关键点是分层 oracle。生成失败、场景失真、API 语义错误和活性错误被分别记录。否则，一个无法编译的测试和一个发现死锁的测试会被混在同一失败类别中。

实验证据与边界

论文给出的评估是可行性验证。作者在一个容量为 1 的 Tokio MPSC 场景中使用 7 个事件，模型推导出恰好 2 种合法线性化。实验重复 3 次，每次产生 14 条结构化记录，所有结构和语义检查通过，没有发现目标库缺陷。

这些数字只能说明端到端流程能够运行。论文没有大型 API 集合、缺陷注入、纯提示词基线或不同调度策略的系统比较，因此目前不能判断它比成熟并发测试工具多发现多少错误。

与相关工作的关系

与普通基于性质的测试相比，这项工作更强调资源生命周期和并发关系。与 Loom 等系统化并发测试相比，它负责生成具有明确语义目标的测试骨架，Loom 仍可负责调度探索。

它也补充了 HarnessLLM 一类从已有测试恢复调用场景的方法。已有测试提供真实使用方式，Petri 网可以进一步把这些方式扩展成新的状态和并发组合。

对研究方向的具体启发

主方向是 Tile Fuzz。可以为 TileLang kernel 建立类似的资源状态模型。令牌表示全局内存 tile、正在传输的 tile、LMEM 中可读 tile、计算中的 tile 和可复用 buffer。变迁表示 DMA、计算、同步和覆盖。随后从模型中生成合法流水、接近非法的依赖缺失，以及高冲突的 buffer 复用测试。

次方向是 LLM for unsafe Rust。unsafe 并发 API 的验证入口可以先由状态模型决定，再让大模型完成具体对象构造，减少无效 harness。

Hardware-Software Co-Design for Float16 On-Device Training on RISC-V Single-Core

Tile for DSARISC-V 半精度训练完整软件路径，向量性能仍待实测

中文理解：用标准 RISC-V 半精度扩展支持资源受限设备上的完整训练
论文版本：arXiv:2607.21130v1，2026 年 7 月 23 日
来源：arXiv 论文页

先给结论

输入是资源有限的单核 RISC-V 平台和需要本地训练的神经网络；系统扩展嵌入式训练框架，使模型、梯度和优化器能够使用 float16，并连接标准 Zfh 与 Zvfh 指令；输出是内存约减半、精度基本保持的完整训练路径和对应硬件代价分析。

读懂它需要的最少背景

设备端训练（On-Device Training）指模型在终端本地完成微调或持续学习。它可以保护数据隐私并减少网络依赖，但训练需要保存权重、梯度、激活和优化器状态，内存压力远高于推理。

RISC-V 的 Zfh 扩展提供标量半精度浮点指令，Zvfh 提供向量半精度能力。使用标准扩展的好处是软件接口更稳定，但标准指令存在并不自动代表训练框架已经支持完整反向传播，也不代表性能一定理想。

3 分钟理解

总览。论文以 AIfES 嵌入式训练框架为基础，把 float16 从一个存储格式扩展成完整训练数据类型。系统补齐前向、反向、优化器、模型转换和层冻结，并给出 Zfh 标量实现和 Zvfh 向量实现方案。结果是模型和主要工作区约减少一半，同时维持接近 float32 的任务精度。

旧方法。资源受限设备常使用 float32 训练。一个 10 万参数模型仅权重就需要约 400 KB，训练还需梯度和中间状态。改用 float16 存储可以减半，但如果每个算子都临时转回 float32，转换和工作区会抵消收益。另一种做法是开发专用训练加速器，但软件会绑定特定硬件。

问题位置。半精度训练的困难位于完整软件路径。只有矩阵乘支持 float16 还不够，损失函数、反向传播、参数更新、模型导入和冻结层都必须保持一致。论文改变的假设是，资源受限训练不一定需要专用 ISA，可以先围绕标准 RISC-V 扩展建立可移植基线。

扩展训练框架。在 AIfES 中加入 float16 张量和算子接口，使前向、梯度和优化器状态可以按统一类型流动。
加入模型转换。把已有 float32 模型转换成 float16 参数，并保留层结构和训练配置。
支持层冻结。微调时只为可训练层保存梯度和更新状态，进一步减少内存和计算。
映射标准指令。标量路径使用 Zfh，向量路径按 Zvfh 设计批量加载、计算和存储。
验证训练结果和硬件代价。比较数据集精度、模型内存和在 FPGA 软核中加入 Zfh 的逻辑资源开销。

完整例子。论文训练一个五层多层感知机，批大小为 128，训练 20 个 epoch。权重、梯度和主要工作区改为 float16 后，模型内存由约 100.85 KB 降为 50.43 KB。使用 SGD 时，MNIST 精度从 float32 的 96.88% 变为 float16 的 97.29%；使用 Adam 时从 97.32% 变为 96.78%。这说明精度变化较小，但不同优化器的数值敏感性不同。

回扣。方法有效的原因是软件和硬件使用同一套标准数据类型接口，内存收益贯穿整个训练过程。它依赖模型能够容忍 float16 精度，也依赖底层实现避免频繁升精度转换。论文尚未闭合 Zvfh 在真实向量硬件上的端到端性能。

关键机制再拆一层

论文最值得关注的是标准接口先行。Zfh 和 Zvfh定义了编译器可以依赖的稳定语义。硬件可以在内部采用不同流水和数据通路，训练框架不需要知道这些细节。

层冻结则说明，后端优化不能只看 dtype。哪些参数需要梯度、哪些中间状态需要保留，也会改变 tile、存储和计算映射。

实验证据与边界

MNIST 与 FashionMNIST 上，float16 和 float32 的准确率差距整体较小。模型权重内存约减半，梯度和工作区也大致按相同比例下降。作者在 NaxRiscv 软核中加入 Zfh 后，LUT6 增加 1.15%，触发器增加 0.05%，频率保持 175 MHz。

当前性能证据有限。完整训练主要通过 RISC-V 指令集模拟环境验证。Zvfh 的向量结构给出了实现方案，但缺少真实 VPU 或 FPGA 上的训练加速和能耗数据。因此，论文证明了软件完整性和低硬件面积，尚未证明向量路径能达到多大加速。

与相关工作的关系

与自定义训练加速器相比，这项工作优先建立标准 ISA 上的可移植路径。它与 Jack of All Scales、ExaGEMM 等硬件扩展研究形成对照：前者扩大标准能力的使用范围，后者为特定格式或模式增加专门单元。

对研究方向的具体启发

主方向是 Tile for DSA。设计 tile 抽象时，dtype 不能只是字段名称。目标描述还应包含累加类型、向量宽度、转换代价、梯度是否保留和冻结层信息。这样编译器才能决定同一 tile 在训练与推理中的不同存储和流水策略。

这篇论文也提醒硬件后端研究先建立可执行的标准基线，再证明专用扩展相对标准路径的真实收益。

7 月 26 日｜Kernel Agent 的评测边界

当日研究信号
当天重点从“模型能否写代码”转向“系统怎样可靠选择代码”。最重要的结论是，编译、正确性、计时和工作负载必须由独立框架管理；代码智能体只负责提出候选和解释证据。

Harness Engineering for LLM-Driven GPU Kernel Generation

Agent kernel DSLKernel 评测框架B200 真机与完整候选轨迹

中文理解：用独立评测框架约束大模型生成 GPU kernel，并以完整工作负载决定候选晋升
论文版本：arXiv:2607.17979v1，2026 年 7 月 20 日
来源：arXiv 论文页

先给结论

输入是算子定义、官方基线、工作负载分布和 GPU 性能证据；评测框架固定编译、正确性、计时与晋升规则，优化控制器只在这些边界内生成候选；输出是可追溯的 kernel 版本、失败证据和经过全工作负载确认的保留实现。

读懂它需要的最少背景

GPU kernel 生成系统通常包含两部分。代码智能体负责写 Triton、TileLang 或 CUDA 代码，评测程序负责编译、运行和计时。如果智能体能够修改评测脚本、只选择有利 shape 或改变计时边界，就可能产生看似很快却没有可比性的结果。

评测框架（Harness）不是普通测试脚本。它还规定候选生成预算、参考实现、错误容差、预热方式、重复次数、工作负载范围、性能晋升条件和证据保存方式。

3 分钟理解

总览。论文把 GPU kernel 自动优化设计成“不可修改的评测框架加基于证据的控制器”。评测框架负责守住任务和数据，控制器阅读 profiler 与历史候选，只提出有限修改。候选只有通过代表性测试、完整工作负载和高次数复测后才会保留。

旧方法。常见 Agent 流程是生成代码、运行一个 benchmark、看到加速就继续修改。这个流程容易出现三类问题。第一，候选只在一个 shape 上更快。第二，计时脚本与官方基线不一致。第三，错误候选和失败尝试没有保存，模型会重复走相同路径。

问题位置。性能优化的难点不只在代码生成，还在“谁定义成功”。若成功条件由同一个 Agent 临时决定，优化结果无法审计。论文改变的假设是，Agent 不应同时扮演选手和裁判。

固定任务技能。人工整理每个算子的数学语义、shape 范围、参考实现、已知硬件限制和 profiler 使用方法。
代表性门禁。候选先在少量能快速暴露错误和明显性能问题的 shape 上编译、差分和计时。
证据驱动修改。控制器根据 profiler、工作负载分布和上轮失败原因，限制 Agent 每轮只修改少量机制。
完整扫描。代表性门禁通过后，候选必须在官方对齐的全部 shape 和 dtype 上运行，不能只报告最优样例。
归档和晋升。保存源码、编译日志、正确性、各 shape 延迟和失败原因。只有整体分布改善且无回归时才替换当前最佳版本。

完整例子。设一个注意力 kernel 在序列长度 128 上快 30%，但在长度 4096 上因寄存器压力慢 20%。代表性门禁可能先发现前者具有潜力，完整扫描会发现后者回归。评测框架不会把该候选直接晋升，而是把“长序列寄存器压力”加入下一轮证据。Agent可以减小 tile 或增加另一版本，而不是只围绕短序列继续优化。

回扣。方法有效的原因是，它把性能优化转成可审计的候选选择问题。它依赖高质量参考、合理的工作负载分布和稳定的计时环境。专家技能仍然占有重要地位，当前结果不能视为完全自主优化。

先给结论

输入是黑盒 GPU 和一组跨计算单元的访存时延测量；系统分离 L2 与 DRAM 延迟、过滤噪声并聚类每个 SM 的延迟特征；输出是 GPU 内部的 NUMA 节点、SM 与存储节点关系，以及本地和远程访问代价。

读懂它需要的最少背景

非一致存储访问（Non-Uniform Memory Access，NUMA）表示不同计算单元访问同一层存储时，延迟可能不同。CPU 系统通常公开 NUMA 节点，GPU 内部的 L2 分片和 DRAM 分区关系往往不公开。

如果编译器假设所有存储访问代价相同，它可能把生产者和消费者放在距离较远的计算单元上，也会让模拟器低估远程访问。

3 分钟理解

总览。DGNA不依赖厂商私有指令，而是通过跨流多处理器的微基准测量缓存和显存延迟。系统把每个 SM 对不同地址区域的延迟整理成向量，再用统计聚类恢复 NUMA 拓扑。最终得到哪些 SM 更接近哪些 L2 或 DRAM 节点，以及远程访问需要额外多少周期。

旧方法。常见 GPU 微基准在一个线程块中反复访问地址，通过缓存命中和未命中估计延迟。这种方法容易把 L2、DRAM、刷新和调度噪声混在一起，也很难判断不同 SM 访问同一地址是否走相同路径。

问题位置。隐藏拓扑的证据来自“同一数据由不同 SM 访问时的稳定差异”。若基准无法分别控制数据位于 L2 还是 DRAM，就不能确认差异属于哪一层。论文改变的假设是，不必得到内部物理文档，也可以从完整延迟分布反推结构。

构造跨 SM 测量。一个 SM 先访问目标地址，使数据进入 L2；另一个 SM 随后读取，从而测量跨 SM 的 L2 路径。
构造 DRAM 路径。通过缓存冲刷或足够大的工作集，让请求绕过已有缓存状态，测量显存访问。
过滤异常样本。使用高斯混合模型区分主要延迟分布和刷新、抢占等离群事件。
形成延迟向量。对每个 SM，记录它访问多个地址分区时的 L2 和 DRAM 延迟。
聚类恢复拓扑。延迟模式相近的 SM 被归为同一 NUMA 组，并进一步推断 L2 与 DRAM 节点之间的关系。

完整例子。假设 SM0 访问地址分区 A 的 L2 延迟约 218 周期，访问分区 B 约 379 周期。SM1 的模式相反。系统会推断 SM0 更接近 A，SM1 更接近 B。如果同样的远程差值也出现在 DRAM 路径中，说明远程 DRAM 请求可能先经过远程 L2 互连，而不是直接进入显存控制器。

回扣。方法有效的原因是，拓扑会在大量重复测量中形成稳定的相对延迟模式。它依赖较强的实验控制和统计分离。厂商改变缓存策略、地址哈希或调度器后，需要重新测量，推断结果也不等同于官方物理结构图。

关键机制再拆一层

最关键的设计是延迟向量。单个平均值很难识别拓扑，一个 SM 对多个分区的整组延迟模式更像它的“位置指纹”。

高斯混合模型的作用也很实际。GPU 访存数据包含刷新和系统噪声，直接取均值会把少量高延迟事件误认为拓扑差异。

实验证据与边界

在 A100 上，本地与远程 DRAM 延迟约为 385 和 546 周期，本地与远程 L2 约为 218 和 379 周期。在 H100 上，对应值约为 554/728 和 295/470 周期。相近的本地远程差值支持远程 DRAM 路径与 L2 互连相关。

证据来自真实 A100 和 H100。论文研究的是黑盒推断，结论应理解为与测量一致的拓扑模型。它没有覆盖 AMD GPU，也没有证明所有工作负载都能通过 NUMA 感知放置获得相同比例收益。

与相关工作的关系

与传统 GPU 性能模型相比，DGNA提供目标硬件事实，而 TileSight、GPU-Tile-Sim 等模型可以消费这些事实。它与 profiler 的区别是，目标不是解释某次 kernel，而是恢复长期稳定的存储结构。

对研究方向的具体启发

主方向是 Tile for DSA。新 DSA 的目标描述不应只记录峰值带宽和统一延迟，还要记录计算单元到存储分区的距离矩阵、地址映射和跨节点通信代价。

次方向是 TileLang-TPU。多核 TPU 后端可以将 tile 放置和 buffer 分配写成拓扑感知问题，并用微基准自动生成目标配置，而不完全依赖厂商文档。

3 分钟理解

总览。WaveformQA把真实硬件仿真波形变成一个可复现问答基准。每个问题都有程序自动计算的答案。研究者比较 VCD 和事件时间 JSON 两种表示，观察模型在简单查询、事件排序和多信号推理上的能力。

旧方法。现有硬件大模型基准主要要求生成 Verilog 或解释代码，波形通常只是附加上下文。模型可能会根据代码猜测行为，而没有真正读取执行轨迹。另一方面，直接把长 VCD 放进上下文会消耗大量 token，信号值还需要根据时间增量恢复。

问题位置。困难出现在表示和推理两层。VCD 虽然紧凑，却把事件语义藏在格式中；即使转成直白事件，模型仍要处理跨多个周期和多个信号的因果关系。论文改变的假设是，硬件 Agent 的波形能力需要独立评测，不能由代码生成成绩替代。

选择可复现设计。从五个开源 RISC-V 核生成仿真波形。
程序化生成问题。问题分为八类和二十四个子类，包括值查询、持续时间、事件顺序和多信号关系。
计算真值。脚本直接扫描波形，得到确定答案，避免人工标注错误。
比较输入表示。同一波形分别提供 VCD 和按时间列出的 JSON 事件。
分析错误。按问题类别、波形长度和上下文溢出统计准确率。

完整例子。问题要求判断复位信号下降后，取指请求和总线响应哪个先变化。模型必须先找到复位下降时刻，再在两个信号的后续事件中寻找第一次变化，并比较时间。VCD 中信号名可能被短编码，值只在变化时记录；JSON 则明确写出时间、信号和值。实验显示，后者虽然 token 更多，却显著减少格式解析错误。

回扣。方法有效的原因是它把硬件时序推理从主观演示变成有程序真值的基准。它依赖波形问题能够被脚本准确表达。复杂协议语义、模拟信号和大型 SoC 的更长轨迹仍未覆盖。

关键机制再拆一层

另一个机制是程序化真值。基准可以持续加入新波形和问题，而不必依赖人工逐题判断。

实验证据与边界

基准包含 360 个问题、8 个类别、24 个子类别和 5 个 RISC-V 核。Claude 4.6 总体准确率约 64.7%，Gemini约 57.8%。部分模型因上下文溢出表现很低。波形从 5000 个变化扩展到 30000 个变化时，准确率下降约 8 至 12 个百分点。

最难的类别包括时间顺序、哪个信号先变化和触发后周期数。基准规模仍然有限，且集中在 RISC-V 数字波形。它能测量能力边界，不能直接证明模型在真实调试流程中能提高多少效率。

论文版本：arXiv:2607.22432v1，2026 年 7 月 24 日
来源：arXiv 论文页

先给结论

输入是 tile 化 kernel、目标 GPU 参数和跨设备放置；系统在 tile 内建模计算与搬运，在 tile 间建模依赖和缓存复用，在设备间建模通信；输出是单 GPU、融合 kernel 和多 GPU 服务的延迟、缓存命中与配置排序。

读懂它需要的最少背景

TileLang、Triton 和 CUDA Tile 都让程序员按 tile 描述计算。现有性能工具却常使用整个算子的运算量，或依赖训练数据的黑盒模型。它们难以解释融合 kernel 中多个 tile 怎样重叠，也难以迁移到新硬件。

解析性能模型（Analytical Performance Model）根据硬件吞吐、带宽、延迟和程序结构计算性能。它可解释、成本低，但必须选择合适的建模粒度。

3 分钟理解

总览。TileSight用同一个 tile 抽象连接三个层次。单个 tile 被表示为网络、内存和计算流水中的资源需求；多个 tile 通过数据依赖、程序顺序和缓存复用关系调度；跨 GPU 的远程 tile 访问再映射到通信拓扑。输出不仅是总延迟，还包含各层限制和候选 tile 的相对排序。

旧方法。屋顶线模型把 kernel 压成运算量和数据量，无法表示软件流水和合法重叠。机器学习成本模型能拟合复杂关系，但需要目标硬件数据，换到新架构容易失效。指令级模拟精细，却难以快速探索大量 tile 配置和多 GPU 放置。

问题位置。现代 kernel 的性能由 tile 之间的时间关系决定。两套 tile 具有相同 FLOPs 和字节数，若一套允许异步加载与计算重叠，另一套因依赖必须串行，延迟会不同。论文改变的假设是，tile 既是代码生成单位，也可以成为性能分析的稳定接口。

建立 tile 内资源向量。记录一个 tile 在片上网络、全局内存、共享缓存、张量核心和普通核心上的工作量。
调度 tile 间动作。根据数据依赖、顺序依赖和资源限制，计算哪些动作可以合法重叠。
预测缓存复用。从 tile 的重用距离估计 L2 等多级缓存命中，而不要求完整地址级模拟。
映射跨设备访问。将远程 tensor tile 关联到设备放置和通信路径，用启动延迟与带宽模型估计代价。
比较候选。对不同 tile、融合边界和设备放置重复计算，选择预测最优配置。

完整例子。考虑融合注意力 kernel。一个 Q tile 先从显存进入片上存储，随后与多个 K tile 执行矩阵乘，再由普通核心完成 Softmax，最后和 V tile 相乘。TileSight为这些阶段建立资源向量。K tile 的重复访问决定缓存命中，Softmax 与下一块 K 的加载是否能重叠由依赖图决定。若 K/V 位于远程 GPU，还要加入网络路径。模型最终给出这一 Q tile 的关键路径，并据此累积整 kernel 延迟。

回扣。方法有效，是因为 tile 粒度保留了决定性能的局部结构，同时比指令级模拟更简单。它依赖规则 tile 程序和可获得的硬件参数。数据相关控制流、不规则访问和隐藏 CTA 调度仍较难建模。

关键机制再拆一层

TileSight的关键不是单个公式，而是三个层次共享同一标识。一个 tile 在编译器 IR、缓存模型和跨设备通信中保持对应关系，便于解释误差和迁移。

缓存部分使用重用距离而非逐地址模拟，使模型能够覆盖融合 kernel 和多级缓存，同时控制分析成本。

实验证据与边界

实验覆盖 A100、H200、B200 和 B6000。单 GPU kernel 的合并平均绝对百分比误差为 12.35%，L2 命中率预测在各 GPU 上大致与实测相差一个百分点。最多 32 GPU 的融合分布式 kernel 加权误差为 16.18%，端到端 vLLM 服务为 13.52%。

模型能选择与厂商和专家基线竞争的 tile 配置。论文计划在正式发表后开源。局限包括规则 tile 假设、缺少数据依赖控制流，以及部分硬件调度和拓扑参数不可见。

与相关工作的关系

与 TileFlow相比，TileSight补充了跨线程和缓存层次的性能分析。与 GPU-Tile-Sim相比，它更偏解析和跨设备，而后者更强调事件式执行与同步。

与 Ansor 的学习型成本模型相比，TileSight依赖较少测量数据，更适合新架构初期，但精度受硬件参数质量限制。

Kani 是面向 Rust 的有界模型检查工具。验证 unsafe 函数时，研究者需要写 proof harness，并明确指针有效、长度匹配、对象初始化和别名等前置条件。

3 分钟理解

总览。KaPilot先从函数文档中提取安全要求，再让规格生成 Agent 把要求转换成 Kani 条件。预检查和验证 Agent循环检查语法、可满足性和证明结果，最后通过候选间的蕴含关系选择较强且可验证的规格。

旧方法。代码中心的 LLM 会根据实现猜测前置条件。若实现本身漏掉检查，模型可能把缺陷当成预期语义。另一些系统只要求 Kani 证明通过，模型可能加入“长度永远为零”一类过强条件，使验证失去意义。

问题位置。规格的来源和质量判断都不稳定。论文改变的假设是，安全意图应优先从文档提取，候选规格还要比较强弱，而非只看能否编译和证明。

轻量分析和 harness。提取参数、控制流和可能的内存操作，建立基础验证入口。
提取安全要求。SafetyReq Agent阅读文档，整理指针、长度、初始化、别名和生命周期要求。
生成规格。SpecGenerate把自然语言要求转成 Kani假设、断言和循环不变量。
预检查和验证。检查规格能否满足、是否存在空洞证明，并将编译或证明错误反馈给生成 Agent。
选择最终候选。打乱候选顺序并比较逻辑蕴含，优先选择覆盖更广且不弱于其他候选的规格。

完整例子。假设 unsafe 函数从裸指针读取 len 个元素。文档规定指针必须非空、指向至少 len 个已初始化元素，并且内存不能在调用期间被其他可变引用修改。KaPilot先把这些要求分解，再生成 Kani 假设。如果模型只写 len == 0，预检查可能发现候选过强，候选间蕴含比较也会显示它覆盖范围过小。

回扣。方法有效，是因为安全要求、规格生成和规格评估被分开。它依赖文档质量和 Kani 的有界验证能力。循环边界、复杂别名和缺少文档的函数仍可能失败。

预检查还负责识别不可满足规格和空洞证明，防止“限制所有输入”带来的虚假成功。

读懂它需要的最少背景

性能分析器能告诉开发者标量单元、向量单元、内存和同步分别占多少时间，但它通常不能直接说明是哪行 DSL 代码产生了这些行为。中间表示（Intermediate Representation，IR）提供源代码和目标指令之间的转换证据。

新 NPU 后端的指令、布局和降级规则复杂，代码表面上的简单操作可能触发标量化、同步或额外转换。

3 分钟理解

总览。论文把 kernel 优化定义为逐层诊断。系统先用低成本规则寻找常见问题，再读取 profiler。只有当前证据仍不能解释瓶颈时，才进入 IR 和编译器源码。找到原因后，Agent才修改源代码。

旧方法。普通 kernel Agent看到延迟后直接尝试改 tile、循环和融合。某次加速只说明修改有效，不能说明原因。若真正瓶颈来自后端没有原生指令，模型可能连续修改源码却始终没有改善。

问题位置。运行时症状与编译决定之间缺少对应关系。论文改变的假设是，优化前应先确定“为什么慢”，而且分析深度应按需升级。

代码模式分诊。检查串行归约、重复转换、明显错误的 tile 和冗余搬运。
性能诊断。读取各执行单元、指令类型和同步的占比，形成可能原因。
IR 归因。把异常标量操作、同步和 layout 转换对应到源代码中的具体算子。
编译器依据。必要时检查后端实现，确认目标是否有原生能力，以及当前降级为何发生。
证据支持的改写。只生成能够消除已确认瓶颈、并保持语义的修改。

完整例子。论文中的分组评分 kernel 需要找每组最大的两个值并求和。直观实现先执行 argmax，屏蔽最大值位置，再找第二个最大值。Profiler显示约 26% 操作进入标量路径，IR 中出现 26 次同步。后端分析表明普通 max 有高效向量路径，带索引的 argmax 需要跟踪和传播标量索引。作者改为在固定大小组内计算非对角两两和，再做纯向量最大值。虽然比较次数增加，但取消了索引和同步，50 个测试全部通过并获得 1.42 倍加速。

回扣。方法有效，是因为每次修改都能对应到运行时和编译证据。它依赖后端开放 profiler、IR 和源码。封闭编译器只能完成前两层分析。

关键机制再拆一层

系统的层次并不要求每个问题都追到后端源码。简单问题在代码模式层即可修复。深层分析经常用于排除错误方向，例如确认某个同步是语义所需，不能通过源码小改删除。

这提示诊断输出应包含证据强度和未确定项，而不是只给一条优化建议。

实验证据与边界

系统在 Ascend 950 基准中评估 37 个成功转换的算子。初始到优化 kernel 的几何平均加速为 4.35 倍，中位数 2.73 倍；22 个超过 2 倍，13 个超过 5 倍。

最佳版本出现轮次的中位数约为第 10 轮。多数最终修改可归因于代码模式层，深层分析的直接获胜案例较少，说明其主要价值可能是解释和排除。论文没有完整消融每层对最终性能的独立贡献，且结果集中在 Ascend Triton 后端。

论文版本：arXiv:2607.23099v1，2026 年 7 月 25 日
来源：arXiv 论文页

先给结论

输入是当前批次的专家路由直方图和 token 数；系统用离线构造的可控偏斜分布评测多种 kernel，再在 GPU 上匹配实时分布；输出是接近最优的融合 MoE 实现选择。

读懂它需要的最少背景

混合专家模型（Mixture of Experts，MoE）会把每个 token 路由到少数专家。每个专家实际收到的 token 数可能不同。融合 MoE kernel 通常需要为每个专家分配 tile，并对不足的部分填充。

很多服务系统只按批次总 token 数选择 kernel。但相同总数下，均匀分布和集中到少数专家的分布会产生完全不同的 padding、并行度和数据复用。

3 分钟理解

总览。论文先建立一个能够控制路由偏斜的评测方法，证明最佳 kernel 会随 token 数和专家分布一起变化。随后，DA-MoE在 GPU 内读取实时路由直方图，与离线调优过的分布原型匹配，并选择对应 kernel，避免 CPU 同步。

旧方法。静态 token 桶会认为两个拥有 1024 个 token 的批次相同。若第一个批次均匀分给 64 个专家，每个专家约 16 个 token；第二个批次大部分集中在 8 个专家。前者需要许多小 GEMM，后者形成少量大 GEMM。相同 tile 策略很难同时适合。

问题位置。性能决定因素被一个总量指标掩盖。论文改变的假设是，MoE workload shape 应包含完整或压缩后的分布特征。

定义分布指标。使用有效专家数压缩路由偏斜，数值越低表示负载越集中。
反向生成分布。使用 Dirichlet 模型产生具有指定偏斜程度的专家直方图，形成可控 benchmark。
离线调优。在不同 token 数和偏斜分布上测量多种融合 MoE kernel，保存近优区域。
在线提取。路由完成后直接在 GPU 上得到实时直方图和压缩特征。
GPU 内分派。匹配最近的离线分布并选择 kernel，避免把信息复制到 CPU 后再返回。

完整例子。两个批次都有 2048 个 token。均匀批次的专家 token 数接近，适合让更多线程块并行处理各专家；偏斜批次只有少数专家很大，适合更大的 M tile 和不同的并行分配。DA-MoE根据直方图选择不同 kernel，而不是把它们放在同一个 2048-token 桶中。

回扣。方法有效，是因为运行时特征与真正的 kernel shape 对齐。它依赖离线库覆盖常见分布，在线匹配开销足够低。遇到训练分布外的路由、动态专家并行或新硬件时需要重新调优。

关键机制再拆一层

有效专家数是一个低成本特征，但它可能把形状不同的直方图压成相同数值。因此系统仍需要更丰富的匹配或回退策略。

GPU 驻留分派避免 CPU-GPU 往返，这一点对于短 kernel 很重要，否则调度开销可能抵消收益。

实验证据与边界

在 HumanEval-X 服务轨迹上，DA-MoE相对静态策略，使 DeepSeek-V3 的融合 MoE 几何平均延迟提高 1.16 倍，Kimi K2 提高 1.29 倍，峰值分别为 1.40 和 1.56 倍。完整 MoE 层的收益略低。

实验在 NVIDIA B200 和真实 MoE 模型上进行。结果依赖离线 kernel 库和分布覆盖。论文没有证明同一指标能适用于所有专家并行、量化和多节点配置。

与相关工作的关系

与 AutoTVM 的 shape-based dispatch 类似，DA-MoE也从离线测量中选择版本，但它把数据分布加入 shape。

DOPS进一步把算子设备放置和权重布局纳入决策，NELSSA则处理请求长度和状态迁移。三者共同扩展了运行时特征。

抽取场景。从测试中识别对象创建、方法调用、状态准备和断言，合并相似调用模式。

3 分钟理解

总览。论文先从真实缺陷中恢复 TorchDynamo 前端承担的职责，再把缺陷按根因组织。分类结果被转成定向测试模板，大模型只负责组合能触发某类语义问题的 Python 程序。测试分别在普通执行和 torch.compile 下运行，并比较返回值、异常和对象状态。

预填充和解码具有不同计算特征，因此常被分配到不同设备。另一种常见方法使用屋顶线模型，把计算密集算子放到 NPU，把带宽密集算子放到存内计算设备。

这些方法通常假设每个算子的设备代价固定。真实系统中，shape、设备争用和权重在内存中的持久布局都会改变代价。

3 分钟理解

总览。DOPS把大模型推理拆成带阶段信息的算子图。一个调度器根据当前 shape 和设备状态选择算子位置，另一个布局仲裁器在容量限制下选择权重块布局。两项决定反复更新，直到形成一致计划。

旧方法。预填充—解码分离会把整个阶段固定到某类设备。屋顶线放置则独立判断每个算子更偏计算还是带宽。它们没有考虑同一设备上多个算子的竞争，也没有考虑权重已经按哪种 tile 和顺序常驻。

问题位置。假设一个矩阵乘理论上适合 PIM，但它所需权重当前以 NPU 友好格式存放。重新布局会增加时间和内存。若 PIM 还在执行上一算子，静态放置的收益会进一步消失。论文改变的假设是，算子位置和持久数据布局必须共同决定。

构建阶段图。把预填充、解码和其他阶段中的算子表示为有向无环图，并记录依赖和 shape。
估计动态代价。根据设备能力、当前争用和数据移动估计每个算子在 NPU 或 PIM 上的延迟。
执行双焦点放置。Bifocal 调度器同时观察局部算子收益和全图关键路径，选择设备。
选择权重布局。权重布局仲裁器在容量限制下决定各权重块怎样分块和驻留。
闭环修正。布局改变算子代价，系统重新评估放置，直到得到一致计划。

完整例子。同一 Transformer 层在长预填充中执行大矩阵乘，NPU 计算吞吐更有优势；在小批解码中，权重读取占比提高，PIM 可能更合适。如果 PIM 容量不足以保存全部层权重，WLA只为收益最大的块选择 PIM 布局，其余保持 NPU 布局。Bifocal随后重新计算关键路径，避免为了局部加速引入大量布局转换。

回扣。方法有效，是因为调度决策使用了真实影响延迟的阶段、争用和持久布局。它依赖可用的设备性能模型和离线测量，硬件与运行时变化后需要重新校准。

关键机制再拆一层

DOPS中的“闭环”并非在线反复试错，而是让放置与布局模型相互提供新的代价。任何一方单独优化都可能产生在另一方约束下不可行的方案。

阶段感知图还避免把预填充和解码中的同名算子视为同一工作负载。它们的 shape、批量和关键路径位置不同。

论文版本：arXiv:2607.24854v1，2026 年 7 月 25 日

先给结论

输入是可能不完整或互相冲突的自然语言硬件规格；系统在文本层挖掘不一致，并在仿真层比较多个候选行为；输出是修复后的规格和更高的 Verilog 测试通过率。

读懂它需要的最少背景

自然语言硬件规格常出现模糊词、边界条件缺失和多段描述互相矛盾。大模型即使严格遵循其中一段，也可能生成与另一段不一致的 RTL。

普通 Verilog 生成系统通常把规格视为可信输入。生成失败后再修改代码，很难判断问题来自实现还是任务本身。

3 分钟理解

总览。VClare在代码生成前增加规格修复。文本路径直接寻找描述中的冲突和缺口；仿真路径生成多个可能实现，通过测试行为聚类发现规格允许了互不一致的解释。系统再仲裁冲突并形成较稳定规格。

旧方法。若规格写“计数器在 enable 为高时递增”，另一段又说“每个时钟周期递增”，模型可能选择任一解释。单次生成和仿真只能显示某个实现失败，无法确认哪条描述应被修改。

问题位置。错误发生在需求进入生成器之前。常见的多轮代码修复会围绕不稳定目标反复修改。论文改变的假设是，规格本身也应成为可分析和可执行验证的对象。

文本一致性检查。大模型提取状态、触发条件、优先级和边界行为，寻找同一概念的相互冲突描述。
生成候选解释。对仍然含糊的规格产生多个符合不同解释的 Verilog 实现。
仿真行为聚类。在系统生成的输入上运行候选，根据输出轨迹把实现分组。
冲突仲裁。若多个行为簇都与部分文本一致，系统在测试时选择证据更充分的解释或要求补充条件。
重写规格和生成。将确认的行为写回规格，再生成最终 RTL。

完整例子。一个多模块 FIFO 规格没有说明满状态下写请求和读请求同时到达时的优先级。候选实现可能先写、先读或同时更新。VClare通过仿真观察这些行为分成不同簇，再结合其他描述和测试确定优先级，并把规则写回规格。后续生成不再围绕三种解释反复试错。

回扣。方法有效，是因为它把规格含糊转成可观察的行为分歧。它依赖测试能够区分候选解释，也可能遇到多个行为都合理而缺少外部事实的情况。

关键机制再拆一层

文本修复适合明显矛盾，仿真修复适合表面文字一致但行为仍有多种解释的情况。两条路径互补。

行为聚类不直接判断哪一簇正确，它只暴露规格没有唯一决定行为。最终仲裁仍需要文档、参考测试或用户确认。

NELSSA: GPU-PNM Serving via Length-Based Request Placement

Tile for DSA异构 LLM 服务真实 GPU-PNM 端到端原型

中文理解：按当前上下文长度选择 GPU 或近存设备，并在请求增长后迁移 KV 状态
论文版本：arXiv:2607.26633v1，2026 年 7 月 29 日，MICRO 2026
来源：arXiv 论文页

先给结论

输入是混合长度 LLM 请求、当前 KV 缓存和 GPU/PNM 资源；系统把短请求放 GPU、长请求放 PNM，并在上下文增长后迁移状态；输出是更高解码吞吐和更低长尾延迟。

读懂它需要的最少背景

GPU适合把短请求组成大批次，利用高计算吞吐。长上下文解码需要反复读取大型键值缓存，显存容量和带宽会限制批量。

近存处理（Processing-near-Memory，PNM）设备算力较弱，但靠近大容量内存，适合长上下文注意力。请求长度还会在生成过程中持续增长。

3 分钟理解

总览。NELSSA把请求位置视为动态状态。短上下文请求先在 GPU 高吞吐执行，长请求进入 PNM。运行时监控上下文增长，达到阈值后将请求和 KV 状态迁移到 PNM，不重新计算已完成 token。

旧方法。GPU-only 系统在混合长度批次中被长请求占用大量显存，短请求无法形成大批量。静态异构放置在请求到达时选择设备，但开始很短的请求可能在多轮生成后变长。

问题位置。一次性选择无法适应请求状态演化。论文改变的假设是，设备放置必须包含迁移，并把缓存状态作为一等对象。

按长度初始放置。短请求进入 GPU，长请求进入 PNM。
设备专用 kernel。GPU执行高吞吐解码，PNM执行靠近内存的稀疏注意力。
监控增长。运行时持续记录每个请求的上下文和 KV 容量。
迁移状态。请求跨过阈值时，系统通过 CXL、RPC 和 RDMA 转移 KV 与执行元数据。
继续执行。PNM从现有状态继续解码，不重放历史 token。

完整例子。一个 512-token 请求最初在 GPU。生成数千 token 后，KV 缓存增大，使同批其他短请求无法进入。运行时将该请求的 KV 块和位置状态迁到 PNM，GPU释放显存继续服务短请求，长请求在 PNM靠近大容量内存执行注意力。

回扣。方法有效，是因为设备优势随请求长度变化，迁移让系统重新匹配。它依赖低成本互连和完整状态迁移，阈值不当或迁移过频会抵消收益。

关键机制再拆一层

核心机制是无重计算迁移。系统必须明确哪些状态决定后续解码，包括 KV 缓存、当前位置和采样相关元数据。

长度阈值并非固定硬件常数，它受模型、批量、显存和 PNM 带宽影响，需要运行时或离线校准。

实验证据与边界

作者实现了端到端 GPU-PNM 原型，包括 PNM 侧稀疏注意力、GPU decode kernel 和 CXL 基础设施上的主机运行时。混合长度工作负载中，解码吞吐最高提高 5.5 倍，P99 延迟最高降低 15 倍。

最高收益依赖请求长度分布和硬件配置。真实原型增强了可信度，但系统仍围绕特定 PNM 设备和 CXL 环境，不能直接外推到普通 PCIe TPU。

与相关工作的关系

DA-MoE根据分布选择 kernel，DOPS根据阶段和布局选择设备，NELSSA根据长度与状态增长迁移请求。它把运行时决策扩展到有状态对象。

对研究方向的具体启发

主方向是 Tile for DSA。跨设备运行时需要一个状态迁移合同，明确 tile、KV 块、地址、版本、依赖和恢复点。

对于多 DSA 系统，编译器应生成设备专用实现和保守回退，并让运行时根据状态变化选择。

论文版本：arXiv:2607.27270v1，2026 年 7 月 29 日
来源：arXiv 论文页

先给结论

输入是编译前后结果、多个参考基线和编译配置；系统分别记录差异相对什么产生、证据支持哪种编译机制，以及误差是否真的变差；输出是允许混合、含糊和未知结论的可审计归因记录。

读懂它需要的最少背景

浮点运算不满足严格结合律。归约重排、融合乘加和向量化会改变最后几位。观察到差异并不自动等于误编译，也不自动等于数值质量下降。

许多编译器测试只使用单个误差阈值。阈值失败时，比较基线、编译行为和准确率后果被混在一起。

3 分钟理解

总览。BMOA要求每条数值异常回答三个独立问题。第一，与什么系统边界和基线比较。第二，现有证据真正支持哪种编译机制。第三，相对更高精度或问题参考，结果变好、变差还是无法确定。

旧方法。假设优化后结果与未优化结果差 1e-5。普通测试会根据阈值给出通过或失败。但未优化程序也可能因严重消去误差偏离高精度答案，优化后的融合乘加反而更准确。

问题位置。单一基线无法说明差异来源和后果。论文改变的假设是，数值正确性报告应保留证据边界，而非强制给出唯一归因。

定义基线。明确严格浮点、未优化程序、局部关闭变换、另一编译器或更高精度参考。
检查可复现性。重复运行和固定环境，排除随机与系统噪声。
定位机制。通过局部变换对照、编译器配置和跨编译器比较判断可能的重排、融合或向量化。
评价后果。用高精度或领域参考判断误差增大、减小或无法比较。
保存审计记录。保留输入、编译配置、指标和所有支撑工件。

完整例子。一个交替大正数和大负数的归约容易消去。标量顺序、树形归约和 FMA 路径得到不同末位。BMOA先确认差异相对哪条基线，再通过关闭向量化或融合定位机制，最后与高精度求和比较。若优化结果更接近高精度，记录应写“编译器引入差异但准确率改善”，而非误编译。

回扣。方法有效，是因为它拒绝把不同问题压成一个阈值。它依赖可构造的局部对照和高精度参考。复杂模型中，高精度真值可能不可得，此时应保留未知。

关键机制再拆一层

“未知”是框架的重要输出。证据不足时不应根据相关性推断某个 pass 是原因。

每条记录同时保存操作层差异和领域结果，使后续形式化规格可以基于真实异常模式构建。

实验证据与边界

论文在六个科学计算 kernel、确定性压力输入和 ARM64 Clang 配置上构建 1276 条记录，并形成 162 实例的受控机制矩阵。实验显示基线选择会改变诊断，编译器差异不必然导致准确率下降，消去和大动态范围影响最大。

框架不是证明系统，实验集中在科学 kernel 和 ARM64。深度学习低精度、GPU 并行非确定性和完整模型准确率仍需单独研究。

与传统差分测试相比，BMOA扩展了结果解释。与 Kaizen、SolSmith等生成方法相比，它不负责产生输入，而是负责保存证据和结论边界。

主方向是 Tile Fuzz。数值 oracle应输出基线、schedule 变化、目标 dtype、高精度误差方向和证据强度。

总览。ARES先建立可比较的单次模型调用成本，再实验不同记忆组织和推理强度。系统发现复杂记忆没有稳定收益，于是用耐心计数器监控优化进展。低成本推理连续若干轮没有改善时，才升级到更深推理。

旧方法。固定高推理强度会让简单局部修改也支付昂贵成本。固定低强度则可能在复杂结构优化上停滞。只报告最终 PPA 不报告模型成本，也无法公平比较 Agent。

问题位置。推理资源没有根据任务难度和搜索阶段分配。论文改变的假设是，模型思考深度本身也应成为运行时调度变量。

归一化成本。把不同模型和推理强度的调用换算成统一美元成本，与目标函数一起记录。

监控停滞。若连续若干轮 PPA 没有改善，耐心计数达到阈值。
升级推理。调用更深推理分析结构、关键路径和跨模块修改。
根据新进展调整。获得改善后继续在合适强度搜索，避免每轮固定最高成本。

完整例子。一个乘加单元初始存在明显冗余寄存器，低强度模型可以快速删除。后续性能受跨模块关键路径限制，数轮局部修改没有进展。耐心计数触发更深推理，模型重新组织流水级。综合结果改善后，系统不必在所有后续小修中持续使用最高强度。

回扣。方法有效，是因为推理预算跟随实际停滞，而非预先固定。它依赖综合指标相对稳定，耐心阈值也可能对新设计失配。

输入是同时具有激活稀疏和权重稀疏的 Transformer 张量；Ventaglio直接解码压缩元数据，并在独立累加存储中执行索引乘加；输出是减少缓存和向量寄存器压力的稀疏张量收缩结果。

读懂它需要的最少背景

RISC-V 向量扩展（RISC-V Vector Extension，RVV）能表达通用向量访存和计算。中等稀疏矩阵向量乘需要根据元数据把非零乘积累加到不连续输出位置，普通 RVV 必须用软件解码索引并通过 L1 缓存保存部分和。

屋顶线（Roofline）表示在给定计算与带宽能力下的性能上限。论文发现现有实现距离上限很远，主要损失并非乘法数量，而是索引和累加状态管理。

3 分钟理解

总览。Ventaglio在向量处理集群中加入可配置稀疏执行单元、融合索引乘加指令和独立累加存储。硬件直接理解 1:4、2:4 或位图元数据，完成 gather、accumulate 和 scatter。结果是稀疏 kernel 减少软件索引、L1 往返和 VRF 占用。

旧方法。假设激活向量只有两个非零值。处理每个值时，软件读取对应权重行的压缩数据，解码输出索引，从 L1 或向量寄存器读取旧部分和，执行乘加，再写回。不同权重行可能更新同一输出，过程需要反复索引访存。

问题位置。现有 RVV缺少“根据压缩元数据直接更新展开输出”的原生路径。只增加稀疏乘法指令仍不能解决累加状态存放和地址更新。论文改变的假设是，稀疏执行需要同时设计指令、元数据通路和专用状态存储。

配置稀疏格式。软件告诉执行单元当前使用 1:4、2:4 或位图编码，以及逻辑输出范围。
读取压缩数据。权重值和位置元数据一起进入稀疏执行单元，普通向量指令不再逐项展开索引。
融合索引乘加。新指令用当前非零激活乘权重，并直接定位目标部分和。
使用独立累加存储。展开输出保存在 VRF 之外，但通过逻辑向量寄存器编号访问，减少普通寄存器压力。
自动更新地址。访存指令完成后递增压缩权重和元数据指针，减少循环中的标量地址计算。

完整例子。一个 2:4 权重组只保存两个非零值和它们在四个输出位置中的编号。融合指令读取当前激活和这组数据，直接从专用累加存储取出对应两个部分和，完成乘加后写回。同一输出若稍后被另一行更新，仍在该存储中继续累加，不必在 L1 和 VRF 之间往返。

回扣。方法有效，是因为它同时消除了索引解码、缓存往返、寄存器占用和地址更新四类开销。它依赖稀疏格式稳定且处于中等稀疏范围。接近稠密或极高稀疏时，其他执行方式可能更合适。

关键机制再拆一层

独立累加存储仍使用逻辑向量寄存器编号，兼顾了软件接口和硬件专用性。编译器需要知道哪些逻辑寄存器被映射到该存储，并在容量不足时分块。

Ventaglio覆盖的是通用向量和完整矩阵加速器之间的空白。它适合不规则程度较高、但仍有足够连续工作可摊销控制开销的场景。

实验证据与边界

12 纳米实现中，四通道集群加入 Ventaglio 的逻辑面积增加约 3.1%，目标频率为 1 GHz，没有引入新的关键时序路径。周期级 kernel 仿真相对优化 RVV 基线加速 6.9 至 7.4 倍。

作者用 RTL 校准的指令级模型分析 4×4 集群。DuoGPT 剪枝的 LLaMA-3-8B 在 40% 至 60% 双重稀疏下，预填充加速 2.40 至 5.25 倍，解码加速 2.06 至 3.16 倍。结果来自 RTL、综合和校准模型，没有真实流片芯片；系统功耗、温度和完整软件栈仍需验证。

与相关工作的关系

与普通 RVV 相比，Ventaglio增加专门的元数据和累加路径。与稀疏张量核心相比，它保留向量处理器的灵活控制，更适合矩阵向量和中等稀疏。

ExaGEMM也共同探索 kernel 和 ISA，但关注低比特查表 GEMM。Ventaglio关注稀疏元数据和不规则累加。

对研究方向的具体启发

主方向是 Tile for DSA。稀疏 tile 需要显式描述非零值布局、元数据格式、逻辑输出范围、累加状态位置和融合更新语义。tile 不再只是规则矩形。

次方向是 TileLang-TPU。后端可根据稀疏度和专用存储容量选择普通 TIU、SIMD 或稀疏单元，并生成容量不足时的分块与写回。

先给结论

输入是已经合并的代码变更、现代仓库版本和开发者证据；系统重建变更发生前的任务状态，并验证从健康基线到待修复状态再到恢复状态的完整生命周期；输出是带环境、规格和自动判定的可执行编码任务。

读懂它需要的最少背景

代码 Agent benchmark 需要真实仓库状态、明确任务、可运行工具和可靠测试。直接保存历史 pull request 当时的容器会快速过时，也会重复存储大量相似环境。

仓库历史包含真实开发者变更，但旧补丁往往无法直接应用到当前版本。文件移动、API 演进和测试变化都会破坏任务。

3 分钟理解

总览。Change2Task从已合并变更中抽取任务意图，并尽量把任务重建在现代、可维护的仓库版本上。系统使用补丁反转、代码映射或 Agent 重建得到待完成状态，再验证健康基线、任务状态和恢复状态。最终生成可直接交给编码 Agent 的环境和判定。

旧方法。常见 benchmark 把历史 issue 和对应 PR 绑定到旧 commit。环境可能依赖失效的包和构建工具，任务数量也受限于能成功复现的历史快照。另一种方法只根据 PR 文本生成任务，却可能缺少真正的失败状态。

问题位置。开发者证据位于历史版本，稳定环境位于现代版本。两者之间存在代码演进差距。论文改变的假设是，任务不必永久冻结在旧 commit，可以把变更语义迁移到健康的新基线。

筛选源变更。选择有明确补丁、测试或描述的已合并变更，并归入缺陷修复、功能、测试生成、API 迁移或安全修复。
选择现代基线。在当前维护版本上确认项目能够构建和通过原有测试。
重建任务状态。简单情况反转补丁；代码已移动时建立旧新代码映射；无法机械迁移时由 Agent 重建等价缺陷或缺失功能。
验证三阶段生命周期。健康基线必须通过，任务状态必须出现预期失败，恢复补丁必须重新通过。
封装任务。生成任务描述、工具环境、可见测试、隐藏判定和开发者证据。

完整例子。历史 PR 把一个旧 API 迁移到新接口。多年后文件已经移动，原补丁不能直接反转。系统先在现代版本找到对应调用点，移除迁移后的写法并恢复一个能够编译但未完成新 API 适配的状态。测试必须在任务状态失败，重新应用现代化修复后通过。编码 Agent得到的是当前依赖和工具链，而任务仍来自真实历史变更。

回扣。方法有效，是因为它把任务语义与旧环境分开，同时用完整生命周期验证防止生成空任务。它依赖源变更有足够证据，代码映射或 Agent 重建也可能改变原问题。

关键机制再拆一层

三种重建方法按可信度和成本递增。补丁反转最接近历史事实，代码映射处理重构，Agent 重建覆盖机械方法无法处理的情况。每种任务应记录使用了哪种方法。

健康基线、任务状态和恢复状态三次验证是核心 oracle。只验证最终修复通过，无法确认任务状态真的包含目标问题。

实验证据与边界

从 1130 个可构造源变更出发，系统在五类任务上取得 79.6% 的验证构造成功率。相对基于 PR 的构造基线，验证任务数量增加 29.2%。历史任务与重建任务在 Agent 评测中的结果一致率最高达到 98.0%，复用现代基线使完整流程测得开支降低 10.8%。

这些指标主要评价任务构造质量和成本，不能直接证明使用这些任务训练会提高多少 Agent 能力。Agent 重建任务仍可能产生语义漂移，需要保留来源和重建证据。

与相关工作的关系

与 SWE-bench 一类历史 issue benchmark 相比，Change2Task强调在现代健康版本上复用环境。与 Harness Engineering 相比，它解决 benchmark 从哪里来，后者解决候选怎样评测。

与 Tile Fuzz 的随机生成相比，仓库历史提供真实缺陷和工程场景，可以作为定向生成与回归测试的种子。

对研究方向的具体启发

主方向是 Agent 友好的 kernel DSL。可以从 TileLang、Triton 或后端仓库的历史 PR 自动构建 kernel Agent 任务，包括性能修复、动态 shape 支持、后端适配和测试补全。

次方向是 Tile Fuzz。历史缺陷可转成可执行回归场景，再从每个场景提取语义变异和 oracle，扩大真实错误附近的测试空间。

仍值得继续研究的问题

  1. 统一的 tile 语义合同。计算、资源生命周期、稀疏元数据、动态 shape 和运行时迁移仍分散在不同表示中。
  2. 规格到 oracle 的自动编译。SpecFirst、VClare、KaPilot和HarnessLLM分别处理规格、修复、证明和场景，但 kernel DSL 尚缺统一合同。
  3. 性能和正确性共用的事件表示。TileSight、WaveformQA和编译归因都需要事件与依赖，但目前工具接口不同。
  4. 面向真实缺陷的 Tile Fuzz。需要像 Frontend Bugs 和 Change2Task 一样，从历史缺陷与修复中形成生成模板、回归任务和缩减目标。
  5. 离线预测与在线选择的置信度接口。DA-MoE、DOPS和NELSSA需要知道当前输入是否仍处于离线模型覆盖范围。
  6. Agent 成本的统一计量。ARES只计模型调用，Kernel Agent还需要加入编译、profiler、模拟器、真机测量和人工审阅成本。

术语表

部分序（Partial Order）

只规定真正有因果关系的事件顺序，其他事件允许交换。它适合表示并发测试和异步流水。

非一致存储访问（Non-Uniform Memory Access，NUMA）

不同计算单元访问同一层存储时具有不同延迟或带宽。

值变化转储（Value Change Dump，VCD）

记录数字硬件信号随时间变化的标准格式，适合仿真工具，但对大模型并不直观。

中间表示归因（IR Attribution）

把运行时性能或错误现象对应到编译器中间表示中的具体操作和转换。

有效专家数（Effective Experts）

压缩 MoE 路由偏斜程度的指标，用来区分均匀分布和集中分布。

验证入口（Verification Harness）

为形式工具构造对象、符号输入、调用和待证明性质的程序入口。

图断裂（Graph Break）

前端暂时退出计算图捕获并回到普通执行的边界。状态处理不完整会造成语义错误。

近存处理（Processing-near-Memory，PNM）

在大容量内存附近执行带宽密集计算，减少数据搬运。

基线—机制—后果归因（Baseline–Mechanism–Outcome Attribution，BMOA）

分别记录比较关系、编译器行为证据和数值准确率后果，避免把任意浮点差异直接判为误编译。

专用累加存储（Dedicated Accumulation Storage）

为稀疏或不规则计算保存展开部分和的独立片上存储，减少普通寄存器和缓存压力。

补丁反转（Patch Reversal）

从包含修复的健康版本中反向移除变更，重建待完成任务状态。

替代价值（Replacement Quality）

判断候选 kernel 除了算对之外，是否足够快、稳定并能替换现有实现。
